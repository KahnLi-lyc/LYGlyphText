## 交付的公开接口

| 接口 | 行为 |
|---|---|
| `LYGlyphTextParser(rules:)`、`document(from:)` | 先替换表情短码，再按规则顺序识别动作；与已识别范围重叠的后续匹配被忽略。匹配范围扩展到完整组合字符，属性叠加在原样式之上，动作按原文位置排序后交给 `LYGlyphTextDocument` 统一校验。 |
| `.links()` | NSDataDetector 识别网址，actionID 为 URL absoluteString。 |
| `.mentions()` | `@` 加 Unicode 字母、数字、下划线；actionID 为 `mention:名称`。 |
| `.topics()` | 成对 `#话题#`；actionID 为 `topic:话题`。 |
| `.pattern(_:options:attributes:pressedStyle:actionID:)` | 自定义正则；无效模式不产生匹配，生成空 actionID 的匹配被忽略。 |
| `.emoticons(_:size:alignment:)` | 短码（最长优先）替换为图片附件，替代文本为短码，附件 ID 为 `emoticon-序号`。 |

限制：包含表情附件的匹配（例如 `#话题[笑]#`）不生成动作，避免 actionID 含 U+FFFC；输入原本含未描述的 U+FFFC 时与文档初始化一样抛错。路线图中的“TextView 实时解析”随编辑器一起不做。

## 行为证据

`Tests/LYGlyphTextTests/ParserTests.swift`（5 项）：链接、@提及、#话题# 按原文顺序成为动作，原文片段与样式正确；先前规则覆盖重叠（网址中的 `#a#` 不成为话题）；组合字符完整保留；自定义正则、无效模式与空 actionID；表情短码最长优先替换为附件、替代文本与唯一 ID，后续动作位置正确；含表情的话题不成为动作；输入中未描述的 U+FFFC 仍抛错。
